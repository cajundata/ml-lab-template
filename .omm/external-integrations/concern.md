- **doctl is a subprocess, not a library**, so its error surface is stringly-typed. `create.py` detects a capacity failure by matching the substring `"not available in this region"` in the error text. That works, and it is checked against real DO output — but it is exactly the kind of thing a doctl release can break silently. If creates start failing hard instead of retrying, look here first.
- **DigitalOcean single-GPU capacity flaps across both regions and SKUs, by the minute.** No pinned `(size, region)` pair survives contact with this account. That volatility is an *external* property the code has to absorb, not a bug it can fix.
- **The droplet needs outbound network for the required probe.** `transformers_smoke` pulls `facebook/opt-125m` from the Hugging Face Hub at run time. A Hub outage, a rate limit, or a network-restricted droplet fails a *required* probe — meaning an infrastructure hiccup outside DigitalOcean can fail an otherwise healthy GPU run. There is no local model cache or mirror.
- **The self-destruct path depends on the DO metadata service** at `169.254.169.254`. If that were unreachable, the droplet could not learn its own id and could not delete itself — the last safety layer would be gone. It is retried every 300s, forever, which is the mitigation.
- Machine-local credentials (`doctl auth`, the registered SSH key, `.env`) **do not travel with a `git clone`** and have to be rebuilt on every new machine.
