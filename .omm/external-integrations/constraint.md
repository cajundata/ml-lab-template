- **`doctl -o json` writes errors, INCLUDING 404, to STDOUT — not stderr.** Every error path reads `stderr + stdout` concatenated. Any new doctl call must do the same. Getting this wrong produced a false `TeardownError` at S4 live that would have broken every run, and separately masked an invalid-SSH-key error into a blank message.
- **Two DigitalOcean tokens, never one.** doctl authenticates with the operator's normal token; the **destroy-scoped** token (`DO_DROPLET_DESTROY_TOKEN`) is a separate credential, delivered to the droplet only via cloud-init into `/etc/ml-lab/run.env` at **mode 0600**. The droplet gets exactly the authority to delete itself and nothing more.
- **`probe_destroy_token()` runs before any droplet is created.** Never provision what you cannot destroy. A **404 means good** (the token authenticates and carries delete scope); 401/403 means rejected.
- **SSH is hardened and non-interactive**: `BatchMode=yes` (never prompt), `IdentitiesOnly=yes` (use only the `-i` key, not whatever the agent holds), bounded `ConnectTimeout`, and `UserKnownHostsFile=/dev/null` so ephemeral droplets never pollute `known_hosts`.
- **Every seam is mocked in every test.** No test may touch a live droplet, a real bucket, or the network.
- The pinned slugs in `constants.py` have **no fallback** by design. Changing a region, image, or SKU is a decision, not something the code papers over at runtime.
