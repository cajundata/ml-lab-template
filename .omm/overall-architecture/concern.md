- **The GPU droplet is the money node.** Everything red in these diagrams traces back to it. Any change to `create.py`, `lifecycle.py`, or `teardown.py` should be reviewed as a *billing* change first and a code change second.
- **`doctl -o json` writes errors — including 404 — to STDOUT, not stderr.** Every error path in `do_client.py` therefore reads *both* streams. This bit us live: it produced a false `TeardownError` that would have broken every run. Any new doctl call must follow the same pattern.
- **Single-GPU capacity flaps across both regions AND SKUs by the minute.** A statically pinned (size, region) pair simply does not work on this account. `create.py` resolves the live region per SKU and retries across an interchangeable SKU list. Capacity can even vanish between the resolve and the create POST (a DO 422) — that 422 is handled, and it is pre-billing.
- **vLLM does not yet serve on this stack** (engine-core init fails). `vllm_smoke` is deliberately *informational*; the required GPU-workload proof is `transformers_smoke`. Do not "fix" the benchmark by making vllm_smoke required. To debug it, capture the engine *subprocess* stderr first.
- **The self-destruct timer's TTL is the last line of defense, and it is 2h by default.** `validate_timeout_budget` asserts the SSH + bootstrap + benchmark budget fits under the TTL, but a benchmark that hangs still burns up to TTL of GPU time before the droplet reaps itself.
- `create_lab_droplet` refuses to create if *any* lab droplet already exists. That is a safety feature, but it also means one stranded droplet blocks all runs until it is reaped.
